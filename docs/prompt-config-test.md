## ۰. نقش

تو مهندس ارشد تیم پلتفرم هستی که مسئول مینی‌اپ Cloud Guardian است (React + Vite در `webui-src/`، بک‌اند Go در `server/`، ربات تلگرام در `worker.js`). کدی که می‌نویسی باید با همان الگوهای موجود بخواند، تست داشته باشد، و بعد از انتشار نیاز به دست‌کاری نداشته باشد.

## ۱. هدف

کاربر لینک کانفیگ (vless / vmess / trojan) را در مینی‌اپ می‌چسباند و در چند ثانیه می‌فهمد:

1. آن کانفیگ **واقعاً کار می‌کند یا نه** (نه فقط پورت باز است)،
2. **تأخیر واقعی** عبور ترافیک از تونل چقدر است (میانهٔ چند نمونه، نه یک عدد شانسی)،
3. اگر کار نمی‌کند، **کجا** شکسته است: نام دامنه، TCP، TLS/SNI، هندشیک پروتکل، یا پاسخی برنگشتن.

### غیرهدف‌ها (آگاهانه انجام نمی‌شود)
- تست سرعت دانلود/آپلود (Bandwidth). عدد تأخیر کافی است و سرعت تست، پهنای باند سرور نگهبان را می‌بلعد.
- گرفتن لینک از URL اشتراک. نسخهٔ اول فقط لینک خام؛ «از اشتراک» بک‌لاگ است.
- تست دوره‌ای/کرون. این ابزار دستی است و هیچ نوشتن دوره‌ای در `Store` ندارد (طبق سند UI §14).
- ذخیرهٔ خود لینک. لینک شامل UUID/پسورد است و هرگز روی دیسک نمی‌نشیند.

## ۲. تصمیم‌های قفل‌شده (خلاصهٔ مهندسی)

| موضوع | تصمیم | دلیل |
|---|---|---|
| موتور تست | `xray-core` (باینری رسمی، نسخهٔ پین‌شده، بررسی SHA-256) در `/opt/cloud-guardian/bin/xray` | تنها راه اندازه‌گیری واقعی؛ TCP/TLS تنها «زنده بودن» را ثابت می‌کند نه کارکردن کانفیگ را |
| نبود موتور | حالت `engine_missing` + دکمهٔ «نصب هستهٔ تست» که از `/api/tools/cfgtest/engine` نصب می‌کند | کاربر نباید برای یک ویژگی، SSH بزند |
| تأخیر واقعی | زمان از اتصال SOCKS تا اولین بایت پاسخ `204`، ۵ نمونه، گزارش میانه + p95 + jitter + loss | عددی که با کلاینت واقعی قابل مقایسه است |
| حکم | `ok` اگر ≥۴ از ۵ نمونه موفق، `degraded` اگر ۱–۳، `fail` اگر ۰ | یک نمونهٔ بد نباید کانفیگ سالم را رد کند |
| نمونه‌گیری | ۵ نمونه، ۳۰۰ms فاصله، سقف کل ۲۰ ثانیه برای هر کانفیگ | تعادل دقت/زمان |
| هم‌زمانی | صف سریالی، حداکثر ۲ تست هم‌زمان، سقف ۲۰ لینک در هر درخواست | سرور نگهبان باربر است، نه بنچمارک |
| ذخیره‌سازی | فقط ۵۰ نتیجهٔ آخر، بدون خود لینک: `sha256(link)` کوتاه‌شده + نام + میزبان + پورت + متریک‌ها | حافظهٔ کاربردی بدون نگه‌داری راز |
| SSRF | میزبان‌های خصوصی/لوپ‌بک/لینک‌لوکال/متادیتا رد می‌شوند؛ استثنا با `CG_CFGTEST_ALLOW_PRIVATE=1` | تست = اتصال خروجی با ورودی کاربر |

## ۳. قرارداد API (دقیق)

همه با همان `r.webAuthed(...)` و همان شکل پاسخ `{ok:true,data:…}` که بقیهٔ `/api/tools/*` دارند؛ ثبت در `server/internal/router/webapp.go` کنار بقیهٔ مسیرها.

### `GET /api/tools/cfgtest`
```json
{
  "engine": { "ok": true, "version": "25.9.11", "path": "/opt/cloud-guardian/bin/xray" },
  "limits": { "links": 20, "samples": 5, "timeout_s": 20 },
  "targets": ["https://cp.cloudflare.com/generate_204"],
  "history": [
    { "fp": "9f2c1a7d4b08", "remark": "🇩🇪 DE-01", "protocol": "vless",
      "host": "de1.example.com", "port": 443, "verdict": "ok",
      "median_ms": 128, "loss": 0, "at": 1730000000 }
  ]
}
```

### `POST /api/tools/cfgtest/run`
ورودی: `{ "links": ["vless://…", "vmess://…"], "samples": 5 }`
```json
{ "results": [
  {
    "fp": "9f2c1a7d4b08", "remark": "🇩🇪 DE-01", "protocol": "vless",
    "host": "de1.example.com", "port": 443,
    "verdict": "degraded",
    "pre": { "dns_ms": 18, "tcp_ms": 64, "tls_ms": 96 },
    "samples": [128, 131, 0, 129, 0],
    "min_ms": 128, "median_ms": 129.5, "p95_ms": 131, "jitter_ms": 3, "loss": 0.4,
    "error_code": "no_response", "error_fa": "هندشیک انجام شد ولی پاسخی برنگشت؛ احتمالاً UUID/پورت پنل عوض شده."
  }
] }
```

### `POST /api/tools/cfgtest/engine`
بدون بدنه. نسخهٔ پین‌شده را دانلود، SHA-256 را بررسی، اجراپذیر می‌کند. خروجی: همان `engine` در GET. اگر شبکه بسته بود: `{ok:false,error:"…"}` با پیام فارسی.

### `DELETE /api/tools/cfgtest/hist`
پاک‌کردن تاریخچه. خروجی `{ok:true}`.

### کدهای خطا (`error_code` → `error_fa`)
| کد | معنی | پیام فارسی |
|---|---|---|
| `parse_error` | لینک قابل خواندن نیست | «لینک را نتوانستم بخوانم؛ کامل و بدون فاصله بچسبان.» |
| `blocked_target` | مقصد خصوصی/متادیتا | «این مقصد مجاز نیست (آدرس داخلی).» |
| `dns_fail` | نام حل نشد | «دامنه حل نشد؛ DNS یا خود دامنه مشکل دارد.» |
| `tcp_refused` / `tcp_timeout` | پورت بسته/بی‌پاسخ | «پورت {port} پاسخ نداد؛ فایروال یا پنل خاموش است.» |
| `tls_fail` | هندشیک TLS شکست | «TLS رد شد؛ SNI یا گواهی/REALITY نمی‌خواند.» |
| `engine_start_fail` | xray بالا نیامد | «هستهٔ تست بالا نیامد؛ دوباره تلاش کن.» |
| `handshake_fail` | پروتکل رد شد | «سرور کانفیگ را قبول نکرد؛ UUID/رمز یا پورت اشتباه است.» |
| `no_response` | تونل باز، پاسخی نیست | «هندشیک انجام شد ولی پاسخی برنگشت؛ احتمالاً UUID/پورت پنل عوض شده.» |
| `engine_missing` | باینری نیست | «هستهٔ تست نصب نیست؛ از دکمهٔ بالا نصب کن.» |
| `rate_limited` | سقف درخواست | «کمی صبر کن؛ هر دقیقه ۱۰ تست.» |

## ۴. بک‌اند

فایل جدید: `server/internal/router/webcfgtest.go` (+ `webcfgtest_parse.go` برای پارس لینک‌ها و `webcfgtest_test.go`).

1. **پارس**: تابع `cfgParseLink(link string) (cfgLink, error)` برای `vless://`, `vmess://` (base64 JSON), `trojan://`. فیلدهای لازم: پروتکل، UUID/پسورد، host/port، `sni`, `host` header، `path`, `type` (ws/grpc/tcp/http)، `security` (tls/reality/none)، `flow`, `pbk/sid/fp` برای REALITY. پارس را table-driven تست کن.
2. **ساخت کانفیگ xray**: outbound از نوع پروتکل + stream settings؛ inbound یک `socks` روی `127.0.0.1:<port آزاد>`. فایل موقت با `os.CreateTemp` در پوشه‌ای که `0700` است، فایل `0600`؛ **بعد از تست `Remove`** و `defer` برای حالت خطا. در لاگ xray سطح `warning` و بدون `access` (تا UUID در لاگ نیفتد).
3. **پیش‌بررسی**: `dns` (LookupHost با context)، `tcp` (DialContext به host:port)، `tls` (tls.Dial با SNI؛ برای REALITY رد شدن هندشیک طبیعی است، پس TLS فقط «اطلاعاتی» است و حکم را تعیین نمی‌کند).
4. **تست زنده**: xray را با `exec.CommandContext` بالا بیاور، تا آماده شدن پورت SOCKS صبر کن (poll 50ms، سقف ۳ ثانیه)، بعد ۵ بار `http.Client{Transport: &http.Transport{DialContext: socksDial, TLSClientConfig: InsecureSkipVerify:false}}` روی `https://cp.cloudflare.com/generate_204` بزن. هر نمونه: از `DialContext` تا `resp.StatusCode==204` (بدنه را نخوان).
5. **جمع‌بندی**: `median`, `p95` (روش nearest-rank روی نمونه‌های موفق), `jitter` = میانگین |اختلاف نمونه‌های متوالی موفق|, `loss` = ناموفق/کل. حکم طبق جدول §۲. شکست‌ها را دسته‌بندی کن: اگر xray قبل از نمونه‌ها مرد → `engine_start_fail`؛ اگر SOCKS وصل شد ولی HTTP نبود → `no_response`.
6. **گارد SSRF**: قبل از هر dial، `net.DefaultResolver.LookupIPAddr` و رد هر IP در `127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, ::1, fc00::/7, fe80::/10` و `fd00:ec2::254`. اگر `CG_CFGTEST_ALLOW_PRIVATE=1` بود، اجازه بده (برای کسی که هاست داخلی دارد) ولی در UI خط «مقصد داخلی» نشان بده.
7. **محدودیت‌ها**: سقف ۲۰ لینک، طول هر لینک ۸ کیلوبایت، صف سریالی با `chan struct{}` به ظرفیت ۲، و rate-limit ساده ۱۰ درخواست در دقیقه به‌ازای هر کاربر (`r.webAuthed` شناسهٔ کاربر را دارد).
8. **تاریخچه**: کلید `cfgtest_hist` در `Store`، آرایهٔ حداکثر ۵۰ مورد، فقط فیلدهای غیرحساس. هیچ‌جای کد لینک خام را لاگ نکن؛ یک تابع `redactLink` بساز و تست کن که UUID در خروجی نیست.

## ۵. طراحی رابط کاربری (unslop)

**جهت طراحی (پنج خط):**
- **محصول:** آزمایشگاه کوچک کانفیگ برای کسی که چند ساب را نگه می‌دارد و باید بداند کدام سالم است.
- **شخصیت:** دقیق، ساکت، فنی.
- **دنیا:** اتاق مانیتورینگ شبانه؛ خطوط اندازه‌گیری و چراغ وضعیت.
- **لحظه‌ها:** عدد تأخیر با فونت جدولی و بزرگ در کارت نتیجه؛ نوار نمونه‌ها (۵ میلهٔ باریک، میانه با رنگ اکسنت، نمونهٔ ناموفق خاکستری خالی).
- **امضای محصول:** همان نقطهٔ وضعیت `.cc-st` که در همهٔ صفحات هست؛ هیچ چراغ جدیدی ساخته نمی‌شود.

**قواعد سخت (از unslop + سند UI پروژه):**
- کروم ساکت: کارت‌ها `var(--ds-card)` + `1px var(--ds-hairline)`، بدون درخشش/گرادیان/سایهٔ رنگی. تنها رنگ روشن صفحه، عدد میانه و میلهٔ همان نمونه است.
- بدون ایموجی در UI. آیکون‌ها فقط Phosphor، یک اندازه (۱۸)، به رنگ نقش متنی.
- اعداد فنی لاتین و `font-variant-numeric: tabular-nums`؛ متن‌های فارسی با ارقام فارسی (`faNum`) و اعداد تأخیر با `ms` لاتین.
- موبایل‌اول: در ۳۹۰px یک‌ستونه؛ همهٔ دکمه‌های لمسی ≥۴۰px (کلاس‌های موجود `.cc-rowbtn`, `.cc-actions`, `.cc-chip` همین الان این را رعایت می‌کنند).
- متن‌های کوتاه بدون نقطهٔ پایانی؛ بدون علامت تعجب؛ بدون «هوش مصنوعی» و صفت تبلیغاتی.
- کنتراست متن اصلی ≥۴.۵:۱ در هر دو تم؛ فوکوس‌رینگ برای کیبورد.

**صفحه (شناسهٔ `cfgtest`، عنوان «تست کانفیگ»، آیکون `Pulse`):**
1. `SectionHeader` «تست زنده» با count «{n} لینک» و اکشن «پاک کردن».
2. `SettingsCard` با `textarea` (کلاس `cc-input`, `dir="ltr"`, `rows=4`, `aria-label="لینک کانفیگ"`, placeholder «vless://… یا vmess://… — هر خط یک کانفیگ») + در فوتر: دکمهٔ اصلی «تست کن» و کنارش «افزودن از کلیپ‌بورد» (اختیاری، فقط اگر `navigator.clipboard` بود).
3. نوار وضعیت اجرا (`RunStrip` موجود): «در حال تست ۲ از ۵…» وقتی `busy`.
4. فهرست نتایج به‌صورت `ListRow`: `lead` = `<span class="cc-st up|down">`، `title` = remark یا `host:port`، `meta` = «vless · میانه ۱۲۹ms · ۱ از ۵ ناموفق»، `trailing` = `Badge` با حکم («سالم» سبز / «نیمه» کهربایی / «خراب» قرمز). کلیک روی ردیف → شیت جزئیات.
5. شیت جزئیات: عدد بزرگ `median_ms`، ردیف پیش‌بررسی («DNS ۱۸ms · TCP ۶۴ms · TLS ۹۶ms»)، نوار ۵ نمونه (`.cc-bars` که در §۶ اضافه می‌شود)، و اگر خراب بود: جملهٔ `error_fa` + «تلاش دوباره».
6. حالت خالی: `Empty` با «هنوز چیزی تست نشده» + «لینک کانفیگ را بالا بچسبان؛ نتیجه همین‌جا می‌آید».
7. حالت `engine_missing`: `SettingsCard` با عنوان «هستهٔ تست نصب نیست» + دکمهٔ «نصب هستهٔ تست» و توضیح یک‌خطی که فقط یک‌بار دانلود می‌شود.
8. تاریخچهٔ ۵۰ مورد آخر زیر نتایج، با `SectionHeader` «تست‌های قبلی» و دکمهٔ «پاک کردن تاریخچه».

**دسترس‌پذیری:** `aria-live="polite"` روی ناحیهٔ نتایج، `aria-busy` روی دکمهٔ تست، لیبل واقعی برای textarea، شیت با `Dialog` موجود (فokus trap خودش را دارد).

## ۸. معیار پذیرش (DoD)

- [ ] چسباندن ۳ لینک (یکی سالم، یکی خراب، یکی بی‌معنی) در ≤۲۵ ثانیه سه نتیجهٔ درست با حکم و دلیل فارسی می‌دهد.
- [ ] عدد «میانه» با کلاینت واقعی (v2rayNG/xray) در همان شبکه ±۲۰٪ می‌خواند؛ عدد TCP به‌عنوان «تأخیر» نشان داده نمی‌شود.
- [ ] هیچ لینک خامی در دیسک، لاگ یا تاریخچه نیست (`grep` روی `data.db` و لاگ‌ها).
- [ ] `127.0.0.1` رد می‌شود؛ ۲۰ لینک بیشتر پذیرفته نمی‌شود؛ درخواست بیست‌ویکم `rate_limited` می‌گیرد.
- [ ] روی ۳۹۰px بدون اسکرول افقی، دکمه‌ها ≥۴۰px، اعداد tabular، در هر دو تم کنتراست درست.
- [ ] `npx tsc --noEmit`, `npx biome lint src` (۰ خطا), `npx vite build`, `npx playwright test` (همه سبز), `CGO_ENABLED=0 go build/vet/test ./...` و `gofmt` پاک.
- [ ] نسخه bump (VERSION + const Version + BOT_VERSION)، بخش RUNLOG، تگ، دیپلوی با `cg-install.sh update`، و تطابق هش `index-*.js` زنده با بیلد محلی.
